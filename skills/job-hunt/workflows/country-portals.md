# Workflow: country job portals (daily, 18:30)

A primary source (candidate.md Source priority), for users who want roles abroad: keep the portals in `config.platforms.country_portals` (platforms.md "Country portals") open, refresh them every day and put the most relevant roles in front of the user to apply. Default 18:30 local time, after a European working day of new postings and before `outreach-sheet-actions` (20:00) applies the rows the user marks Approved. Skip the run with one line if no portals are configured.

Read: `references/rules.md`, `references/platforms.md` (section "Country portals"), `data/candidate.md`, `references/visa-sponsorship.md`, `references/resume-tailoring.md`, `references/sheet.md`, `references/progress-band.md`; `data/answer-bank.md` only when filling a form.

**State**: `~/.claude/job-hunt/state/country-portals.json` = `{"seen": [job links], "login_needed": {"<portal>": "YYYY-MM-DD"}, "filters_failed": {"<portal>": "<what>"}, "last_run"}`. Create if missing; keep the newest 3000 "seen". Applications still count in `applied[today]` in `state/global-search.json` (one daily quota across all routines).

1. **Progress band**: shared `job-search-<today>` entry (progress-band.md), your steps pages-refresh, data-scan, jd-match, resume-update, sheet-update, apply; links Jobs sheet, Resumes.
2. **Tabs** (pages-refresh): `tabs_context_mcp`, then one tab per configured portal in today's set (platforms.md: "Daily" portals every day, plus group A on even day-of-year, group B on odd), or Firecrawl for public listings when on. Reload a tab already on that portal; open one only when none fits, and leave it open (rules.md 8). Set the search on the page as platforms.md gives it (keywords, English, last 24h, or 3 days if thin). A sign-in wall or signed-out state: note the portal in `login_needed`, read only what is public, never sign in (rules.md 1). A filter that won't set: note it in `filters_failed` and the report.
3. **Read** (data-scan): `get_page_text` per portal. Keep roles matching `profile.targets` at the user's level (`profile.search`). Drop: titles with `exclude_title_words`, intern/Werkstudent/working student/trainee/Ausbildung unless the user wants internships, roles asking 2+ years more than the user has, anything in state.seen or already a Jobs row (same link, or same company + role), staffing reposts, the current employer and excluded companies (rules.md 0), and **any JD that requires a local language** (German, Dutch, French, Danish, Swedish, Polish... at B2 or above, "fluent", "verhandlungssicher", "vloeiend"): keep only languages in `profile.spoken_languages` at the level asked. "Nice to have" a language is fine, put it in Cons.
4. **Shortlist** (jd-match): the top ~12 by title and freshness go to the `jd-matcher` agent (JD text, link, location, portal). Then the sponsorship check per company (visa-sponsorship.md: NL register, Germany Blue Card default "likely" for full-time roles at established companies, UK register, Ireland permits). Drop fit under `quota.min_fit_score` and sponsorship "no" (a role in a country where the user can already work needs no sponsorship check). Rank tier 1 first (all of these are abroad, so sponsorship strength decides order), then fit. Keep at most 6.
5. **Resumes** (resume-update): build the tailored one-page PDF for each kept job with the right country preset (resume-tailoring.md), into `<resume_dir>/<today>/`.
6. **Sheet** (sheet-update): Jev on the kept jobs (sheet.md, Q), then one Jobs row each: Region = country, Source = the portal name exactly as platforms.md lists it, Pros with the "Sponsors: ..." line, Status "Ready to apply". Plus up to 5 language-ruled-out roles with the closest titles as "Not eligible" (reason "Needs German C1" etc. in Cons), so the user can see the portals were read. Append, read back, sort (sheet.md).
7. **Ask** (apply): one table in chat, ids P1..P6: portal, company, title, city, posted, fit (why / missing), sponsorship evidence, Jev, link. Ask which to apply to. Apply now only to the ids the user names (rules.md 2): in-site where the portal applies in-site (platforms.md), otherwise the company form as sheet-actions.md step 6 "Career page" does (no-account forms only; an account wall = "Apply on site"). Attach the tailored PDF. Confirmed = "Applied" + `applied[today] += 1`. If the user doesn't answer, leave the rows "Ready to apply": setting one to Approved in the sheet gets it applied at 20:00.
8. **Report**: portals read today (and which need the user to sign in, which filters failed), listings seen / kept / ruled out (main reasons), rows added (company, role, country, score, link), applied, waiting on the user.
