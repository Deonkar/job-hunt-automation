# Workflow: daily company scan

Read: `references/rules.md`, `data/candidate.md` (Source priority), `references/visa-sponsorship.md`, `references/resume-tailoring.md`, `references/sheet.md`, `references/progress-band.md`; `data/answer-bank.md` only when filling a form. Work in the project folder (SKILL.md, Paths).

1. **Progress band**: report to the shared `job-search-<today>` entry (progress-band.md) with links Jobs sheet, Resumes, Companies tab `...#gid=<companies_gid>`, today's CSV `file:///<home>/.claude/job-hunt/out/jobs/<today>.csv` (absolute path).
2. **Feeds** (pages-refresh, data-scan): `PYTHONUTF8=1 py -3 scripts/scout.py --days 2`. Polls the watchlist companies with public feeds, filters title/region/freshness by `profile.search`, dedupes against `data/seen.json`, writes `out/jobs/<today>.json` + `.csv`. Report its summary line and feed errors.
3. **Browser-only companies**: entries in `data/companies.json` with `"ats": "chrome"`. Keep one open tab per company (all of them), parked on its careers search (the first `profile.search.keywords` term where the site has search): `tabs_context_mcp`, open tabs only for companies that have none. Each day reload and read a third of them: sorted by name, index i where i % 3 == day-of-year % 3. Note roles matching `profile.targets` at the user's level, in `profile.search.regions`. Skip anything behind a login.
4. **JD match** (jd-match): career pages are a primary source (candidate.md Source priority). Take the top 15 (scout score >= 50, plus browser finds). Delegate to the `jd-matcher` agent (Agent tool, subagent_type "jd-matcher"): pass `out/jobs/<today>.json` path, the browser finds (company, role, link, location, JD text), and the project path. It returns one JSON object per job (fit score, pros, cons, variant, country, patch overrides, resume_changes, skills_to_learn). Drop jobs under `config.quota.min_fit_score` (45), and any job at the current employer or an excluded company (rules.md 0).
5. **Resumes** (resume-update): per kept job, write the patch file and build + render (resume-tailoring.md), into OUT. Every PDF pages=1. Then write `out/applications/<today>/top.json` (always this local path): kept jobs tier 1 first (candidate.md Location preference), then fit score, each `{company, role, location, region, link, score, tier, pros, cons, resume_changes, skills_to_learn, resume_pdf (absolute, forward slashes, in `<resume_dir>/<today>/`)}`. The referral workflow reads it. Add band links for the top 3 resumes.
6. **Sheet** (sheet-update): one Jobs row per kept job (sheet.md columns), Source "Career page", Status "Ready to apply", Resume = the PDF's path in `<resume_dir>/<today>/`. Append, then read back to confirm.
6b. **Ask** (apply): one table in chat, ids C1..: company, role, location, tier, score, Jev, fit, link. Ask which to apply to. Apply now only to the ids the user names (rules.md 2), on the company form as `sheet-actions.md` step 6 "Career page" does (no-account forms only, tailored PDF attached; an account wall = "Apply on site"). Confirmed = "Applied" + `applied[today] += 1` in `state/global-search.json`. No answer: rows stay "Ready to apply" (Approved in the sheet gets them applied by the evening sheet-actions run).
7. **Report**: feeds scanned and new matches, browser companies read today, jobs added (company, role, score, link), resumes built and where, anything that failed or needs the user.
