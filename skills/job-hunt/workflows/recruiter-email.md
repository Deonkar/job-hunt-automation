# Workflow: recruiter email for the day's best job (daily, one role per day)

Read: `references/rules.md`, `references/sheet.md`, `data/candidate.md`, `references/resume-tailoring.md`, `references/progress-band.md`.

Once a day, take the single best job found today and email up to 2 recruiters at that company about that role. Contacts come from the user's own SignalHire and Apollo Chrome extensions (`config.recruiter_email_tools`); with neither configured, end at once with one line. Nothing is sent here: the emails become Outreach rows the user approves by picking "Send email", and `workflows/sheet-actions.md` (20:00) sends them.

**State**: `~/.claude/job-hunt/state/recruiter-email.json` = `{"days": {"YYYY-MM-DD": {company, role, job_link, people: [{name, profile_url, title, email, email_source, email_status, gmail_draft_id, status: drafted|sent|skipped}]}}, "companies": {"<company>": "YYYY-MM-DD"}}`. Create if missing.

0. **One role per day**: if `days[today]` exists, end at once with one line.
1. **Band**: feature `recruiter-<today>`, title "Recruiter email", lane jobsearch, links Jobs sheet, Outreach tab `...#gid=<outreach_gid>`. Steps: jd-match (pick), data-scan (recruiters + emails), resume-update, sheet-update; the rest skipped.
2. **Pick the job** (jd-match): `get_values` "Jobs!A1:Q". Candidates are rows with Date found = today, Status not Not eligible / Skipped / Wrong search / Not approved / Rejected, Jev (Q) starting "Yes", not the current employer (rules.md 0), and company not in `companies` within the last 30 days. **Visa-sponsored international roles first**, in this order, taking the first group that has a candidate:
   1. Roles outside the user's home country that sponsor a visa (skip this group if the user does not want to move abroad): Region, Pros or Cons say sponsorship / relocation / "Will sponsor", or the company's `visa-sponsorship.md` verdict is yes / likely (run the check if it has none), and Q doesn't name "location". If today has none, look back over the last 3 days' rows for one (same filters) before moving on.
   2. Remote roles at companies headquartered outside the home country (tier 1, no visa needed), today only.
   3. Any other candidate from today.
   Within the group, primary sources first (candidate.md Source priority: Career page and country portals), then rank by Score (G) + 100 x Jev's number in Q (e.g. 72 + 100 x 0.68 = 140), ties by Score. Take only the top one, and say in the report which group it came from. No candidate in any group: record `days[today] = {"none": true}`, report "No job today with a Jev yes", end.
3. **Recruiters** (data-scan), Claude in Chrome, signed-in LinkedIn: search `https://www.linkedin.com/search/results/people/?keywords=<company> recruiter <the user's field>` (e.g. "technical recruiter", "sales recruiter"), then `<company> talent acquisition` if needed. Pick up to 2 people whose profile shows they currently recruit at that company, preferring people who hire for the user's function and the job's country or region. Skip anyone at the current employer, anyone already in `state/outreach.json`, and anyone emailed before (state).
4. **Emails from the extensions**: on each chosen profile, open the **SignalHire** extension and reveal the contact; if it shows no work email, try **Apollo** on the same profile. Keep only a work email at the company's own domain, with its status (verified / valid / guessed) as the tool shows it; skip a "guessed", invalid or personal address. Never take or store phone numbers or personal emails, and never guess or pattern an address yourself. Each reveal spends the user's credits: at most 2 reveals per tool per run. If an extension shows a login screen, no panel, or no credits, stop using it, never log in (rules.md 1), and say so in the report. No usable email means that person is skipped.
5. **Resume** (resume-update): the job's tailored PDF; build it now if the row has none (resume-tailoring.md, "Every application uses its tailored resume") and write its path to Jobs column L.
6. **Draft** each email (rules.md 3, 4, 12; English, under 150 words): subject "<Role> at <Company>: <the user's full name>". Body: who the user is in one line (current title and kind of company, years of experience, from candidate.md), the role and its link, "I applied on <Source> on <date>" if Status is Applied, two JD-specific proof points from candidate.md, "resume attached", a clear ask (a short call, or passing it to the hiring manager), an easy out, the user's sign-off (`config.sign_off`, else their first name). Create a Gmail draft with the Gmail connector (`create_draft`) to that address; the connector can't attach files, so sheet-actions attaches the resume when sending.
7. **Sheet** (sheet-update): one Outreach row per person (sheet.md columns A-N): Date, Person, Title, Company, Job, Job link, Profile, Action "Email draft", Status "Awaiting approval", Notes "Recruiter email; address from <SignalHire|Apollo> (<status>)", Resume = the PDF file name, Connection note and DM empty, Email = the full email (subject line first, then body). Append, read back. Update state (`days[today]`, `companies[company] = today`).
8. **Report**: the job picked and why (Score, Jev, runner-up), recruiters found, emails found and from which tool, drafts made, credits used per tool, anything blocked. Remind the user: pick "Send email" on the Outreach row by 20:00 to have it sent tonight.
