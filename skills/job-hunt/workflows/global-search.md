# Workflow: global search and apply (every 3h, 6am-midnight local time)

Read: `references/rules.md`, `references/platforms.md`, `data/candidate.md`, `references/visa-sponsorship.md`, `references/sheet.md`, `references/progress-band.md`; `data/answer-bank.md` only when filling a form.

**State**: `~/.claude/job-hunt/state/global-search.json` = `{"profile_edit_date", "profiles_checked": {"linkedin", "naukri", "indeed", "wellfound", "waas"}, "seen": [...], "applied": {"YYYY-MM-DD": n}, "secondary_applied": {"YYYY-MM-DD": n}, "linkedin_applied": {"YYYY-MM-DD": n}, "last_full_run"}`. Create if missing; write back at the end (keep the newest 3000 "seen").

0. **Pace check first** (before loading other tools): quota is `config.quota.daily_applications` (default 10-15) a day across all routines (`applied[today]`). These sites are secondary (candidate.md Source priority): this workflow applies to at most `quota.secondary_daily` (5) a day of its own (`secondary_applied[today]`). If (applied[today] >= the quota's low end or secondary_applied[today] >= secondary_daily) and last_full_run < 6 hours ago, reply "Quota met (n applied today); next full search after <time>" and end. Otherwise set last_full_run = now.
1. **Progress band**: report to the shared `job-search-<today>` entry (progress-band.md; mark only your own steps, never skip the company scan's), links Jobs sheet, Resumes, and the profile of each platform used.
2. **Profiles**: the daily Naukri edit is its own task (`naukri-profile-daily`); don't do it here. Run `workflows/profile-refresh.md` (full optimization) only for a platform in use that was never checked or was last checked 30+ days ago, and only with the user's yes per edit.
3. **Search** (data-scan): every platform on in `config.platforms` (platforms.md: LinkedIn Easy Apply with the hour's rotation, Indeed, Naukri, Wellfound, Work at a Startup), searching each `profile.search.keywords` term. Keep titles that match `profile.search.include_title_words` and the user's level (`profile.search.years`, about +1 year at most); drop titles with `exclude_title_words`, roles asking 2+ years more than the user has, staffing reposts, duplicates, anything in state.seen, and any job at the current employer or an excluded company (rules.md 0).
4. **Shortlist** (jd-match): tier 1 first (candidate.md Location preference), then rank by fit (candidate.md best-fit roles; skill and domain overlap, the company types the user prefers, freshness). Skim the top ~12 JDs (or hand them to the `jd-matcher` agent if more than 6). Offer at most min(secondary_daily - secondary_applied[today], quota high end - applied[today]) jobs, LinkedIn within its cap. Ids: N Naukri, L LinkedIn, I Indeed, W Wellfound, Y Work at a Startup. Run Jev on the shortlist now (sheet.md, Q) and reuse those cells in step 6. One table: id, site, company, title, exp, location, posted, fit (why / what's missing), Jev, skills to learn, link; plus the drafted note for each W/Y job. Ask which to apply to. If that number is 0 or less, log finds as "Next day" instead of offering them.
5. **Apply** (resume-update, apply): only the ids the user names. Per job, build its tailored resume first and attach it where the site allows (resume-tailoring.md, "Every application uses its tailored resume"), then apply (platforms.md per site; forms from answer-bank.md). Count each submission in applied, secondary_applied and (LinkedIn) linkedin_applied.
6. **Sheet** (sheet-update): a Jobs row per shortlisted job, plus the ruled-out YC rows (platforms.md, YC): Resume changes = what the tailored resume changed, with "(not attached: <site> sends the profile resume)" when it couldn't be uploaded (plus the note's gist for W/Y); "Profile resume on <site>" for jobs not applied to yet. Skills to learn from the JD, Resume = the tailored PDF path (or "Profile resume on <site>" if none built yet), Source the site, Status Applied / Needs your answer / Apply on site / Not approved (offered, the user didn't pick it; the user can set Approved later) / Not eligible (ruled out for years, contract, location or excluded company, reason in Cons; location only per visa-sponsorship.md, never for a JD that is just silent on visas) / Next day. Append, read back.
7. **Report**: profile work, found / shown, applied (site, company, title, link), waiting on the user, applications today vs the daily quota (LinkedIn count), failures.
