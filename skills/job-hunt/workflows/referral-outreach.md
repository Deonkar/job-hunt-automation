# Workflow: LinkedIn referral outreach (daily, top 2 jobs)

Read: `references/rules.md`, `workflows/sheet-actions.md` (the Action/Status flow), `data/candidate.md`, `references/sheet.md`, `references/progress-band.md`.

**Inputs**: the `top.json` files from the last 2 days in `~/.claude/job-hunt/out/applications/<date>/top.json` (yesterday's and today's; a day's top jobs can be worked the next day). Also Jobs sheet rows dated today or yesterday (global-search finds), except Status Skipped / Wrong search / Not approved / Rejected. Candidates are jobs not yet in state; "the 2 best" means tier 1 first (candidate.md Location preference; use `tier` from top.json, else judge from Location, Region, Pros/Cons), primary sources before secondary within a tier (candidate.md Source priority), then highest score. Use a tier 2 job only when fewer than 2 tier 1 jobs exist, and say so in the report.
**State**: `~/.claude/job-hunt/state/outreach.json` = `{"people": [{name, profile_url, headline, company, role, job_link, resume_pdf, resume_url, status: drafted|invited|messaged|stale|skipped, invited_at, messaged_at, note, dm, email, gmail_draft_id}], "invites": {"YYYY-MM-DD": n}}`.

1. **Band**: `referral-<today>`, links Jobs sheet, Outreach tab.
2. **Follow-ups first**: people "invited" 24h+ ago: open profile_url; now 1st-degree means set their Outreach row Action "Send DM", Status "Awaiting approval" (DM text in column M); still pending after 7 days means "stale". If their own "Contact info" lists an email, prepare an email.
3. **New people** (skip if the shared cap is reached, rules.md 5): for the 2 best candidate jobs (Inputs), first look in `~/.claude/job-hunt/state/linkedin-connect.json` for people already invited at that company: open each profile, and anyone now 1st-degree gets a DM draft straight away (no connection note needed). Then search `https://www.linkedin.com/search/results/people/?keywords=<company> <the target role | its hiring manager title | recruiter>`. Up to 2 people per job, preferring: same team/function, the hiring manager for that function, a recruiter for that function, alumni of the user's school (`config.school_for_alumni_search`), same city/region, 2nd-degree. Confirm current company and title on the profile. Never pick anyone who works at the user's current employer, and never work a job there (rules.md 0).
4. **Drafts**:
   - Connection note (<200 chars): "Hi <first>, I'm a <the user's role in a few words, from candidate.md> applying for <role> at <company>. Would love to connect and ask a quick question about the team. - <sign-off>"
   - DM (<900 chars): thanks (if new), role + link, two JD-specific lines of fit (candidate.md proof points), resume attached, a clear ask ("would you be open to referring me?"), an easy out, the sign-off. Attach the tailored PDF (resume_pdf, in `<resume_dir>/<date>/`; build it first per resume-tailoring.md if the job has none).
   - Email (only for emails from their own contact info): create a Gmail draft with the Gmail connector (`create_draft`): to that address, subject "Referral request: <role> at <company>", body adapted from the DM. The connector can't attach files, so before sending, open the draft in Gmail (Chrome) and attach resume_pdf with `file_upload`. Store gmail_draft_id.
   One table: id (C connection, D DM, E email), person, title, company, job, degree, full text. Ask which to send.
5. **Send only approved ids**: C: Connect (maybe under "More") then Add a note, paste, send; status invited, invited_at, count it. D: Message, paste, attach resume_pdf with `file_upload` on the message box's file input, confirm attachment, send; status messaged. E: only if the user named it, open the draft in Gmail (Chrome), attach resume_pdf with `file_upload`, confirm it shows, send. Confirm each before the next.
6. **Sheet**: one Outreach row per person (sheet.md), columns A-N including Resume, Connection note, DM and Email, Status "Awaiting approval". For follow-ups, update the existing row (Action, Status, DM/Email text) instead of adding one. Append, read back. The user can approve from the sheet by picking a "Send ..." status; `sheet-actions` picks that up.
7. **Report**: follow-ups (accepted / pending / stale), new people, sent, waiting for approval, Gmail drafts created, invites today / this week, any LinkedIn warning.
